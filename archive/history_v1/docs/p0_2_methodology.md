# P0-2 全量质量审计口径

本阶段只读取 `Raw_Dataset`，写出审计小表。没有执行去重、时间对齐、补零、删站点或雨量修正。解析和聚合均由 Spark 完成，Python 只保存已经聚合的小表及检查结果。

## 运行与复现

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts\run_spark.py src\01_audit_raw.py --self-test --output outputs\p0_2_audit\self_test_repeat
.\.venv\Scripts\python.exe scripts\run_spark.py src\01_audit_raw.py --output outputs\p0_2_audit\repeat
```

第二条读取全部八年。已存在结果目录不会默认覆盖；中断后用同一个目录加 `--resume`。恢复前核对代码、运行辅助脚本、原始 manifest、原始文件大小/mtime 签名；仅复用校验全部通过的年度检查点。原始内容 SHA-256 沿用 P0-1 当日已全文复核的 manifest，本次运行前后另外检查大小/mtime，不把这个检查说成重新计算全文哈希。

资源为 `local[4]`、driver 4 GiB、48 个 shuffle 分区、AQE 开启；时区 `Asia/Singapore`、Java 17、PySpark 3.5.7。逐年处理，解析表使用磁盘缓存，键聚合使用内存/磁盘缓存，每年结束释放缓存。

## 记录与解析

每年先验证 12 列表头。Spark text 读取全部物理行，然后用 Spark `from_csv` 和显式字符串 schema 解析每条非表头行，保留原行及 `_corrupt_record`。引号转义设为 CSV 双引号，未转义引号设为 `RAISE_ERROR`，关闭 CSV 列裁剪，保留解析异常。

Spark 的宽松 CSV 解析可能把少列补 null、多列截断，因此另用引号外逗号分割统计字段个数，并检查引号总数是否为奇数。每条物理行按一条候选记录处理，奇数引号提示可能的跨行记录，不能认定为有效行。若有这类记录，必须另行确认多行 CSV 语义。当前数据是否存在由全量结果决定。[Spark 3.5.7 CSV 文档](https://spark.apache.org/docs/3.5.7/sql-data-sources-csv.html)

主时间、整体更新时间、雨量更新时间分别用 `yyyy-MM-dd'T'HH:mm:ssXXX` 解析。雨量及经纬度转换为 double；非空但转换失败、空值、NaN/Infinity、负雨量分别计数。有限坐标检查地理合法范围：经度 [-180,180]、纬度 [-90,90]，没有根据人工划定的新加坡包围框删除记录。

正式规模同时列出几个口径：

- `spark_record_rows`：Spark 扫描并尝试解析的全部非表头记录，含异常记录。
- `structurally_valid_rows`：CSV 未标记损坏、恰好 12 字段、引号不为奇数。
- `key_eligible_rows`：结构合格，站点 ID 非空，观测时间可解析。
- `unique_station_time_keys`：上述行的 `(原始 station_id, 解析后的 epoch 秒)` 唯一键数。
- `candidate_valid_rows`：键合格、雨量有限且非负、单位 `mm`、类型 `TB1 Rainfall 5 Minute Total F`、观测年与年度文件一致、date 与本地日期一致。
- `candidate_unique_keys`：至少有一条候选有效行的唯一键数。

候选有效数仍不是正式清洗交付数：尚未裁决时间偏移、同键冲突、精确重复、坐标/元数据使用等规则；更新时间和坐标问题独立审计，没有仅因更新迟或坐标问题删除雨量事实。

## 重复与元数据

重复键使用站点 ID 和解析后的秒级观测时间；未自动 trim 或改写 ID。输出重复组数、涉及行数、超出唯一键的行数，以及雨量/单位/类型原文不同的冲突组数。精确重复使用 12 个原始字段的 struct 做精确比较，统计键合格范围内的重复多余行；没有用近似 hash 判断。数字原文 `0.2` 与 `0.200` 会作为不同读数原文，这类冲突需要下一阶段核对数值等价性。

站点名、device ID、经纬度原文按组合保存行数及首次/最后出现 epoch；另统计数字经纬度变体，避免把纯格式变化当作数值坐标变化。组合的首末时间是出现范围，不能证明其间每时刻都使用该组合，更不能直接认定站点实际搬迁。跨年小表保留全期变体和各年首末观测之间的间隔。

## 时间刻度与覆盖

`offset_s = epoch 秒 mod 300`，0 是五分钟标准网格，299 表示比下一网格点早一秒。保留年度和每日偏移分布。按站点对唯一时间排序，计算相邻间隔，区分 300 秒、大于/小于 300 秒、非 300 的整数倍；元数据/雨量冲突不会增加时间间隔数量。

station-month 表覆盖每年出现过的所有站点的 12 个月，零观测月份也保留：

- 完整月分母是 `月天数 × 288`，闰年二月用 29 天。
- 诊断槽位是 `floor(epoch / 300)`，只用于覆盖审计，不是推荐或已经实施的时间修正。
- 完整月覆盖率 = 占用诊断槽位数 / 完整月分母。
- 观测跨度分母 = 当月首末诊断槽位之间的槽位数（含首末），给出跨度内覆盖率。
- 独立保存原始唯一时间数、偏移相位数、偏移时间数和“唯一时间数减占用槽位数”，用于暴露混合相位的槽位碰撞。

未观测槽位包括站点尚未投入/已停止观测的时段，不能全部称作设备丢失数据。跨度口径也不能保证站点中间连续在役。这两个比率均为观测覆盖描述，不用于直接补零。候选有效行对应的覆盖率另外提供。

## 更新延迟与异常样例

分别计算两个更新时间减观测时间的秒数，输出负延迟、超过一天的行数、min/max、近似 p50/p95/p99（Spark `percentile_approx`，accuracy=10000），以及分桶交叉计数。数据集更新时间是历史记录中的字段，不能从它推出首次到达延迟或可用于训练的实时可用时刻。

每个异常条件全量统计后最多留 5 条例子；每年最多 30 组重复、30 条较长非标准间隔、15 条最大候选雨量。样例用于定位，异常数来自全量聚合。大雨量样例没有自动作为错误删除。不同异常条件可重叠，不能将各条件计数直接相加当作删除量。

## 验收检查

逐年核对：表头唯一、Spark text 行数与解析候选数闭合、与既有物理行数清单一致、键数与重复多余行闭合、单位/时间偏移分组总和闭合、元数据行数闭合、相邻间隔数等于唯一键数减站点数、station-month 计数闭合及覆盖率范围。全部年度通过后才生成汇总 PASS；运行状态另记录 Java 进程是否正常关闭。

合成夹具检验：短行/长行、带逗号名称、非法时间/数字、空值、NaN/Infinity、负雨量、单位错误、精确重复和冲突重复、299 秒相位、槽位碰撞以及闰年二月。验收通过不意味着原始数据没有异常，只意味着程序正确执行了这些审计检查。
