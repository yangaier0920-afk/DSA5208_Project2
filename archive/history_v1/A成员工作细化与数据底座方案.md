### 3.1 观测表 observations

粒度：一个站点、一个有效观测时间一行。单一测量类型确认后，主键为 `(station_id,event_ts)`；若发现多个真实测量类型，原始去重键需先包含 `reading_type`，再明确哪些类型进入雨量事实表。

| 字段 | 类型与含义 |
|---|---|
| station_id | string；关联键，不能用站点名称替代 |
| event_ts | timestamp；解析原 `timestamp` 对应的时间点 |
| event_epoch_s | long；同一时间点的 Unix 秒，用于窗口与排序 |
| timestamp_raw | string；原始时间字符串，可追溯秒偏移 |
| local_date, year, month | 新加坡本地日期及分区字段，由 event_ts 派生 |
| rain_mm | double；该记录五分钟雨量，保留原精度 |
| station_name_raw, station_device_id | string；保留观测时元数据 |
| longitude, latitude | double；观测时坐标，不能用未来元数据回填 |
| update_ts, reading_update_ts | timestamp；更新字段，仅用于审计或另行确认的可用性方案 |
| reading_type, reading_unit | 原始测量类型与单位；全量确认后固定雨量口径 |
| source_file, source_year | 溯源字段，核查文件年份与事件年份一致性 |
| quality_flags | 原因标记；说明时间刻度、重复修订或其他质量问题 |
| data_version | 数据版本，或统一记录在目录级 manifest 中 |

如果后续获准进行秒级对齐，应额外生成 `slot_end_ts`、`alignment_rule`、`alignment_offset_s`；`event_ts` 和 `timestamp_raw` 继续保留。下游必须写明使用哪个时间字段，不能悄悄替换时间。

### 3.2 三张辅助表

- `station_metadata_history`：站点 ID、名称、坐标、观测到的起止时间与来源。起止时间仅代表资料中首次/末次出现，不能认定为真实建站/撤站日期。
- `quality_station_month`：每站点每月的有效唯一记录数、期望时间槽数、覆盖率、间断数、最长间断、元数据问题与数据版本。
- `quarantine`：保留原始记录及拒绝原因，如格式失败、无效关键键、负值、冲突重复、无法解释的时间映射冲突。

### 3.3 targets 与 features 分开保存

`targets` 保持每站点每预测时刻一行，包含 `station_id, prediction_ts, prediction_epoch_s, future_30m_mm, future_n_valid, target_valid, invalid_reason, label_end_ts` 及历史完整性字段。无效窗口的 `future_30m_mm` 为null。E2实际接口以 `fold1_role, fold2_role, fold3_role, final_role` 替代固定split，同一年在不同轮次可以有不同用途。完整字段见 `docs/p0_4_data_contract.md`。

`features` 同样每站点每预测时刻一行，包括历史窗口雨量、有效观测数、历史窗口完整性与时间特征。与 targets 按 `(station_id,prediction_ts)` 一对一关联。字段名应把历史和未来区分清楚，未来累计量绝不能进入模型特征向量。

`threshold_mm` 和 `label` 在训练时展开：`label = 1[future_30m_mm > threshold_mm]`。阈值也进入模型输入。多个阈值共享同一份历史特征；同一站点时刻的所有阈值样本必须处于同一时间分区。

## 4. 清洗规则：先核查，再执行

### 4.1 原始读取与质量账目

使用 Spark 的显式 schema，避免八年文件反复推断类型。可先将 CSV 列全部读为字符串并捕获 malformed 记录，再显式解析数值与时间，区分空值、解析错误和原本合法的零值。Spark 会惰性执行，成功调用 read 不代表已经读完文件，要用实际 count/聚合及写出验收。

质量审计至少包括：

1. 12 个字段的 schema；解析成功行数与坏行数。
2. 关键字段空值、时间解析失败、雨量 NaN/Inf、负值、坐标无效、单位/类型异常。
3. `date` 与新加坡本地观测日期、文件年份与观测年份的交叉检查。
4. 原始唯一键重复数、完全一致重复数、同键不同雨量/元数据冲突数。
5. 每站点时间最小/最大值、相邻差分、五分钟刻度偏移和连续片段。
6. 每年站点清单、station-month 覆盖、名称/坐标变化。
7. 两个更新时间的空值、差异、负延迟和长延迟。

审计行数必须能对应清洗结果：输入解析记录 = 保留记录 + 各类互斥的丢弃/隔离记录。格式错误单独记账；原因标记可多选，但损失记录数只能计一次。

### 4.2 具体清洗建议

| 问题 | 建议规则 |
|---|---|
| 雨量为 0 | 保留；它是有效观测 |
| 整行缺失、空雨量、NaN/Inf | 作为未知；不补成零 |
| 负雨量 | 隔离并统计；不取绝对值 |
| 大雨量/小数位多 | 标记检查，不因数值大或偏离 0.2 mm 刻度就删除；如需阈值，以来源依据或训练期资料确定 |
| 完全重复记录 | 去掉多余副本，保存去重数量 |
| 同键、不同雨量 | 默认先隔离冲突组并统计影响；只有确认修订语义后才按更新时间选版本，不可把重复雨量相加 |
| 同雨量但元数据不同 | 单独归类并保留元数据历史；不要混同完全重复 |
| 站点名称缺失或只是 ID | ID 有效且雨量/时间有效时可保留，名称问题交给元数据层 |
| 坐标变化 | 保留观测时值和历史；不能无依据认定搬迁 |
| 更新时间晚 | 不因为晚更新删除天气观测；它会影响对实时预测的解释 |

任何按“最新修订”生成的数据只支持说明过的历史回溯口径，不能据此声称还原了历史实时数据版本。

### 4.3 2017 年时间刻度是单独的验收项

`08:04:59` 与 `08:05:00` 只差一秒，但映射到五分钟槽时可能落入不同区间。首条记录也意味着不能默认 2017 年从 1 月 1 日零点已有完整数据。

执行顺序：按站点和日期统计偏移，定位 `:59` 与 `:00` 的转换；检查转换处差分和映射后重复；查阅测量区间定义；记录采用的区间起止假设。官方字段说明未明确说明这几个时间戳的区间含义，`5 Minute Total` 本身不足以证明 timestamp 是区间终点。

在定义未明确前，保留原时间并按原始连续片段计算可核验的窗口。不要把整年 2017 删除。若全量审计支持“边界前一秒是同一类区间终点的编码”，可由 A/C 共同确认后仅对该类记录加一秒到候选 `slot_end_ts`，并核查碰撞、跨日期/年边界与可用性。该做法属于项目处理假设，报告应交代。混合刻度处与不能解释的窗口先标记无效。

### 4.4 覆盖率要区分缺测与站点生命周期

非闰年完整日历含 105,120 个五分钟槽，闰年 105,408 个；完整月份期望槽数是天数 × 288。按采用且经过核验的时间口径计算覆盖。

同时提供完整日历覆盖率和“首末观测之间”的覆盖率，第二种明确叫观测跨度覆盖率。没有真实运行起止资料时，不能把首末观测当作真实运行时间，也不能把未建站时段全部认定为设备故障。

B 的跨年主图已选择B1/K1：以八年共同38站点为候选，按比较年份同月站点交集及90%完整日历覆盖资格形成主面板，95%作敏感性检查；这些是项目约定，不是课程要求。清洗后的具体面板见P0-3覆盖交付。站点平均和全站点补充结果应同时报告样本量与覆盖率，不能累加所有站点的雨量后当作新加坡总雨量。不要简单用 `观测总量 / 覆盖率` 填补全年雨量，因为缺测时段可能与天气有关。

## 5. 未来 30 分钟标签及特征的接口

目标为 `P(R[s,(t,t+30min]] > h | t 时刻允许使用的信息)`，严格大于阈值。已确认L1：“记录代表截至派生slot_end_ts的五分钟累计量”，原timestamp保留；这仍是需要披露的项目假设。

规则确认且时间连续时，未来累计量为 t+5、t+10、t+15、t+20、t+25、t+30 六个区间的雨量之和。要求这六个时间槽都存在、数值有效且无未解决冲突，不能仅判断“后六行存在”或“窗口 count 为 6”。

例如 t=14:00，缺少 14:15，即使之后能找到六行，未来 30 分钟累计量仍未知。该样本应 `target_valid=false`、累计量 null，不生成负例。

Spark 实现可按 station_id 分区、以 epoch 秒排序，使用实际时间 range window；整数秒且没有亚秒数据时 `(t,t+1800]` 对应 `rangeBetween(1,1800)`。它提供时间边界，**不自动证明窗口完整**；还需检查六个预期位置、有效值及连续性。只有通过严格连续性验证后，才能把 `lead(1..6)` 用作优化。[Spark rangeBetween 文档](https://spark.apache.org/docs/3.5.7/api/python/reference/pyspark.sql/api/pyspark.sql.Window.rangeBetween.html)

实现前用小型合成片段和真实片段验证：恰好等于阈值、缺一槽、重复/冲突、300 秒正常间隔、异常间隔、`:59` 到 `:00` 转换、跨日、跨年、数据尾部。人工逐条累加，与 Spark 输出比较。

历史特征由 B 实现，建议从月份/小时周期特征、站点、过去 5/15/30/60 分钟累计量和降雨次数开始。历史窗口同样附带有效数和完整性；不允许只把可见的两条雨量相加后叫“过去 30 分钟累计量”。已确认H1要求过去60分钟的12槽完整，下游报告其排除比例；不要未经新决定放宽这一条件。

### 5.1 时间可用性：历史回溯与运行中的预测

原始更新字段显示观测经常晚几分钟甚至数日更新，但字段含义不足以证明这是首次发布时间。本项目应明确选择口径：

- 建议先完成按观测时间构造特征的历史回溯预测，并声明假设已记录的历史观测在预测时刻可取得。现有证据不能支持实时部署结论。
- 如要模拟实际数据可用性，先确认更新时间语义和版本信息，再要求所用记录的可用时间不晚于 t。只拥有最终版本 CSV 时，即使按更新时间过滤，也未必能重建当时的原始版本。

不把更新延迟、未来修订状态当成天气预测特征。C 的 `predict(station_id,t,h)` 还需按相同规则从共享历史数据获取特征，不能只传入三个参数却暗中要求用户手工提供历史向量。

### 5.2 时间划分与边界

已确认E2：训练至2020验证2021、训练至2021验证2022、训练至2022验证2023；按冻结阈值及三年等权平均Brier选择配置。三人统一采用新加坡本地时间边界，完整协议见 `docs/E2滚动验证实验方案.md`。

先按预测时刻划分，并删除标签区间触及下一分区的训练/验证锚点，即分区右边界 B 为排他边界时要求 `label_end_ts < B`。清洗/连续性计算要能读取前后相邻月份或年份的上下文，不能在每个年度 CSV 内独立构造标签后忽略边界。

验证/测试初期可以用前一分区已经发生的历史观测构造特征；预处理器、站点编码、标准化、模型参数与校准只用训练/允许的验证资料拟合。绝不按随机行拆分，也不能用 2024 标签选择阈值、模型或特征。2024 的原始质量审计本身不等于模型调参。

选定配置后按已确认方案用2017—2023重训，再运行2024最终测试，保存对应模型版本；不能根据2024成绩改选E1/E2或调参。

### 5.3 阈值输入与样本规模

已确认V1以数值阈值作为共享模型输入，`0、0.5、1、2、5 mm`作为初始候选；最终有效阈值范围须先由C仅依据最早开发轮训练期（2017—2020）的完整窗口分布与支持情况冻结，不查看后来验证或测试标签来定范围。

原始约 4,854 万条物理行，若对全部锚点展开四个阈值，规模量级可接近 1.94 亿行；实际有效量需经清洗、历史/未来完整性和边界过滤确定。因此：

1. 在锚点层计算并保存一次累计量和特征。
2. C 在训练阶段按需要展开阈值。
3. 初版用确定性、对降雨结果无条件的锚点抽样，例如按 `(station_id,t)` 的固定 hash 选约 10%，保存种子与纳入比例；抽样在阈值展开之前。
4. 正式 Task 1 使用全量汇总。验证/测试优先完整评估；若资源要求抽样，应事先固定代表性方案，并在报告交代。

不要为了增加正例而只选择下雨时刻。欠采样或类别权重可能改变概率解释，需要 C 验证校准，不能只看分类 accuracy。

统一接口接收数值阈值 h，说明训练覆盖的数值范围，不保证范围外可靠性。C 至少检查：输出在 [0,1]；同站点时刻更高阈值的超越概率不应反而增大。必要的校准或单调处理只能用训练/验证资料确定。陌生站点、历史不足、超范围阈值、非五分钟预测时间也要有明确响应策略；初版可限定有效时间网格，并在 README 说明。
